CONTENT TYPE HANDLING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

## RUNNING TEXT (paragraphs, body copy)
Extract verbatim. Preserve paragraph breaks with a blank line between paragraphs.
Do not reflow or merge lines that are visually separate paragraphs.

## HEADINGS AND SECTION TITLES
Prefix with their visual level using markdown:
  # <title text>      (top-level heading)
  ## <title text>     (section heading)
  ### <title text>    (subsection heading)
If level is ambiguous, use ##.

## LISTS (bulleted, numbered, lettered)
Reproduce each item on its own line with its original marker:
  - item text
  1. item text
  a) item text
Nested lists use indentation (2 spaces per level).

## TABLES
Wrap in [TABLE START] / [TABLE END] markers.
Use pipe-separated columns. Include the header row. Align columns with pipes.
If a cell is empty write <empty>. If a cell spans multiple columns, note it as [MERGED: col1-col2].
Example:
[TABLE START]
| Column A | Column B | Column C |
| value 1  | value 2  | value 3  |
| value 4  | <empty>  | value 6  |
[TABLE END]
After the table, write a one-line [TABLE SUMMARY: ...] describing what the table shows and what its key values are. This summary is critical — it lets the query LLM find this table even when the question uses different wording.

## FIGURES, DIAGRAMS, AND ILLUSTRATIONS
Wrap in [FIGURE START] / [FIGURE END] markers.
Write a detailed description covering:
  - What type of visual it is (flowchart, diagram, schematic, photograph, map, etc.)
  - What it depicts or represents
  - All visible labels, annotations, arrows, and their directionality
  - Any legend entries and their meanings
  - Quantitative values visible in the figure
  - The figure number and caption if present (label them: FIGURE NUMBER: / CAPTION:)
Example:
[FIGURE START]
FIGURE NUMBER: Figure 3
CAPTION: System architecture overview
TYPE: Block diagram
DESCRIPTION: Shows three components connected left to right: Client → API Gateway → Backend Service. Arrows are bidirectional between Client and API Gateway (labelled "HTTPS"), and unidirectional from API Gateway to Backend (labelled "gRPC"). The Backend Service connects downward to a cylinder labelled "PostgreSQL DB".
[FIGURE END]

## CHARTS AND GRAPHS (bar, line, pie, scatter, histogram, etc.)
Wrap in [CHART START] / [CHART END] markers.
Extract:
  - Chart type
  - Title (if present)
  - X-axis label and unit
  - Y-axis label and unit
  - All data series names and their approximate or exact values at key points
  - Legend entries
  - Any trend lines, annotations, or callouts
  - A plain-language interpretation of what the chart shows (the trend, the key insight)
Example:
[CHART START]
CHART TYPE: Line chart
TITLE: Monthly Active Users (Jan–Dec 2023)
X-AXIS: Month (Jan to Dec)
Y-AXIS: Users (thousands)
SERIES: "Mobile" — starts at 120k, peaks at 310k in Aug, ends at 280k; "Desktop" — flat around 90k throughout
ANNOTATION: "Product launch" marked at March with arrow pointing to inflection point in Mobile series
INTERPRETATION: Mobile users tripled over the year driven by the March product launch; Desktop usage remained stable.
[CHART END]

## EQUATIONS AND FORMULAS
Write them out in plain text using standard notation.
Wrap in [EQUATION START] / [EQUATION END].
After the equation, add a one-line [EQUATION MEANING: ...] explaining in words what the equation represents.
Example:
[EQUATION START]
E = m * c^2
[EQUATION MEANING: Energy equals mass multiplied by the square of the speed of light.]
[EQUATION END]

## CODE BLOCKS
Wrap in [CODE START lang=<language>] / [CODE END].
Transcribe exactly, preserving indentation.

## FOOTNOTES AND ENDNOTES
Prefix with FOOTNOTE <number>: and place them at the end of the page content, after all other content.

## PAGE METADATA (headers, footers, page numbers, watermarks)
Prefix with PAGE HEADER:, PAGE FOOTER:, PAGE NUMBER:, or WATERMARK: respectively.
Place page metadata at the very top and very bottom of your output.
